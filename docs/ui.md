# 界面规范

> 这份文档约束 develop 前端长什么样：控件怎么选、页面怎么排、移动端怎么收。
> 新加页面或改列表之前先读一遍，代码里已有对应组件，不要再手写一套。

## 1. 三条底线

- 一屏之内要能判断：这个项目是什么、值不值得点进去。列表里的说明至少三行，标题、状态、技术栈不藏。
- 一页只有一个搜索框。搜索命中哪些字段，写在 placeholder 里，例如「搜索项目、说明或技术栈」。
- 可点、可读、可放大：正文不小于 13px，触控目标不小于 34px（手机 42px），输入框在手机上必须是 16px，否则 iOS 会放大页面。

## 2. 基础值（styles.css 顶部变量）

| 项目 | 取值 | 说明 |
|---|---|---|
| 正文 | 14px / 1.55 | 说明、表格内容 |
| 次要文字 | 12.5px | 元信息、提示 |
| 页面标题 | 26px（手机 21px） | 每页只有一个 |
| 分区标题 | 15px | `section-head h2`、面板标题 |
| 控件高度 | 36px（手机 42px） | 输入框、下拉、按钮一致 |
| 小按钮 | 30px（手机 34px） | 行内动作 |
| 圆角 | 6 / 8 / 12 | 小控件 / 控件 / 卡片与面板 |
| 间距 | 4 的倍数 | 8 控件之间，12 区块之间，18-24 分区之间 |

颜色只用变量：`--ink` 主文字、`--ink-soft` 次要、`--ink-faint` 提示、`--line` 描边、`--brand` 链接与焦点、
`--green/--amber/--red` 状态。不要再写死十六进制色值。

## 3. 组件

`ui.tsx` 放通用件：`Avatar`、`Badge`、`StatusBadge`、`TimeAgo`、`Modal`、`Field`、`Empty`、`Skeleton`、
`Pager`、`Toast`。状态文案与配色集中在文件顶部的映射表里，新状态先加映射，不要就地写死。

`filters.tsx` 放筛选件：

- `FilterBar`：筛选栏容器，内部一行排开，右侧显示统计。
- `Segmented`：主筛选（全部 / 我负责的 / 我参与的），一条轨道里的单选。
- `SearchField`：带放大镜与清除按钮的搜索框。
- `SelectField`：次要条件下拉，外观与输入框一致，自带 aria-label。
- `FilterToggle` + `MobileFilters` + `FilterField`：手机端把次要条件收进底部抽屉。

## 4. 列表页

从上到下固定四段：

1. `page-head`：标题、一句话说明、右侧主动作（新建项目）。
2. 主筛选：项目用 `Segmented`，需求用 `tabs`（状态是导航，不是条件）。
3. `FilterBar`：次要下拉 + 搜索 + 右侧统计；手机端只留搜索与「筛选」按钮，其余进抽屉。
4. 列表与 `Pager`。

桌面用表格或整行信息行，手机用 `card-list`：同一份数据渲染两遍，用 `only-desktop` / `only-mobile` 切换。
整行信息行的结构是「标题 + 状态 → 三行说明 → 技术栈与元信息」，标题上的 `stretched` 让整行可点，
行内动作按钮加 `z-index` 浮在链接之上。

## 5. 详情页

顺序是：返回链接 → 标题 + 状态徽标 + 右侧动作 → `detail-facts` 事实行（所有者、创建、更新）→
各分区 `panel`。事实行只放「谁、什么时候」，不要把统计数字塞回去当徽标。

## 6. 表单页

- `page-head` 只放标题与说明，**提交按钮不要放这里**。
- 字段成组用 `form-row-2` / `form-row-3`，900px 以下自动变成一列。
- 提交与取消放在表单末尾的 `form-actions`：桌面右对齐，手机吸底并带安全区。
- Markdown 字段用 `MarkdownEditor`，左写右预览，Ctrl / ⌘ + Enter 提交。
- 输入框下方的提示写「填什么、为什么」，不要写「必填」这种没有信息量的话。

## 7. 断点与移动端

| 断点 | 变化 |
|---|---|
| 900px | 多列栅格塌成单列，编辑器上下排，目录变横排 |
| 720px | 进入手机布局：隐藏顶部导航与页脚，用右上角菜单；表格换卡片；筛选进抽屉；表单吸底 |
| 420px | 隐藏用户名，只留头像 |

手机上还有几条硬规则：顶部导航图标 40px、`env(safe-area-inset-*)` 要留、弹窗改成底部抽屉、
横向滚动的筛选条要能滑到屏幕边缘、输入框字号 16px。

## 8. 可访问性

- 所有可交互元素都有 `:focus-visible` 焦点环；不要用 `outline: none` 覆盖。
- 只有图标的按钮必须有 `aria-label`；分段控件用 `aria-pressed`。
- 颜色不能是唯一的信息载体：状态除了颜色还有文字。
- 图片与头像 `alt` 留空（装饰性），正文里的图片给描述。

## 9. 自测清单

改完页面按这个顺序过一遍：

1. 1440 宽：内容 1120 居中，筛选栏一行，表格列对齐。
2. 800 宽：筛选栏允许换行，不出现横向滚动条。
3. 375 宽：搜索与筛选一行、主筛选可横滑、列表是卡片、提交按钮吸底、无内容被裁切。
4. 空状态、加载骨架、错误提示都要看一眼，不能只有「有数据」时好看。
5. 长标题、长链接、五个以上技术标签各试一次。

本地没有后端时，可以把 `vite.config.ts` 的 `API_TARGET` 指向一个返回固定 JSON 的小服务，
接口形状照 `web/src/types.ts` 造，界面就能独立调试。
